# KIPRIS Document Hub 6.13 · Local Web Edition

## 일반 사용자용 설치

GitHub **Releases**에서 최신 `KIPRIS_Document_Hub_vX.Y.Z.exe`를 내려받아 더블클릭하면 됩니다. 일반 사용자 PC에는 Python, 소스코드, pip 패키지 설치가 필요하지 않습니다. 프로그램이 KIPRIS 통합행정정보를 처리할 수 있도록 Google Chrome 또는 Microsoft Edge는 설치되어 있어야 합니다.

처음 받은 EXE는 함께 게시된 `SHA256SUMS.txt`로 무결성을 확인할 수 있습니다. 조직에서 널리 배포할 때는 Windows SmartScreen 경고를 줄이고 배포자를 확인할 수 있도록 코드서명 인증서로 EXE에 서명하는 것을 권장합니다.

소스 ZIP 방식은 개발·진단용이며, 일반 배포에는 Release의 단독 실행형 EXE를 사용하세요. 저장소 관리자는 [RELEASE.md](RELEASE.md)의 자동 빌드·배포 절차를 따르면 됩니다.

국내 출원번호·공개번호 또는 외국 공개·등록공보 번호 수십 건을 입력하여 문서를 자동 저장하는 Windows용 프로그램입니다.

6.13 버전은 기존 Python 다운로드 엔진을 유지하면서 화면을 `FastAPI + HTML/CSS/JavaScript` 로컬 웹앱으로 제공합니다. 실행하면 명령창 없이 로컬 서버가 시작되고 Google Chrome 창이 최대화되어 열립니다. Chrome이 없으면 Windows 기본 브라우저를 사용합니다.

문헌·PDF가 많아도 목록이 버튼 뒤로 내려가지 않도록 각 목록을 독립 스크롤 영역으로 고정했습니다. `[출원서등 보정]보정서`는 API 및 KIPRIS 화면 다운로드 대상에서 제외하지만 `[명세서등 보정]보정서`와 의견서는 계속 저장합니다.

6.3에서는 선택한 PDF 또는 문헌 폴더 전체를 Windows 휴지통으로 보내는 삭제 버튼을 추가했습니다. 삭제 전 확인창이 표시되며 다운로드 중에는 삭제할 수 없습니다. 또한 웹 화면에서 사용하지 않는 CustomTkinter·Pillow·PDF 렌더링 모듈을 시작 시 불러오지 않고, 행정서류 브라우저도 실제 국내 행정서류 처리를 시작할 때만 준비하도록 변경했습니다.

6.4의 `외부 PDF 텍스트` 버튼은 다운로드 폴더 밖의 PDF를 Windows 파일 선택창에서 최대 100개까지 선택하여 같은 텍스트 추출·복사 창으로 처리합니다. 선택한 실제 경로는 HTML 화면으로 전달하지 않고 실행 중인 Python 처리부에서 일회성 식별자로만 보관합니다.

6.5에서는 화면의 상태 확인 주기를 진행 중 0.8초, 대기 중 4초로 자동 조절합니다. 진단 모드도 반복적인 `/api/status 200 OK` 접근 기록을 출력하지 않고 실제 서버 시작·종료 및 오류만 보여줍니다.

6.6에서는 문헌번호 카드의 `입력 지우기` 버튼으로 직접 입력하거나 파일에서 불러온 번호를 한 번에 비우고 입력란으로 즉시 돌아갈 수 있습니다. 버튼 영역은 좁은 화면에서도 겹치지 않도록 자동 줄바꿈됩니다.

6.7에서는 다운로드가 끝나는 즉시 마지막으로 처리한 문헌 폴더와 PDF 파일을 자동 선택하여 오른쪽 실제 PDF 뷰어에 높이 맞춤으로 표시합니다. 여러 파일이 저장된 경우 해당 문헌에서 가장 최근에 저장된 PDF를 엽니다.

6.8에서는 상단에 `OPD 국제심사정보`와 `Espacenet 특허검색` 바로가기를 추가했습니다. 설치 프로그램은 기존 필수 패키지가 정상이면 네트워크 다운로드를 건너뛰며, 웹 버전에서 사용하지 않는 CustomTkinter·Pillow와 매번 수행하던 pip 업그레이드를 제거하여 첫 설치와 업데이트 시간을 줄였습니다.

6.9에서는 KIPRIS 문서 팝업과 내부 프레임의 `원문/PDF/다운로드/저장` 버튼을 화면 인쇄보다 먼저 실행하고, 해당 다운로드 이벤트와 PDF 네트워크 응답을 저장합니다. 불가피하게 생성한 Chrome 화면 인쇄본은 식별표시를 남겨 다음 실행에서 정상 원본으로 간주하지 않고 원문 다운로드를 다시 시도합니다.

6.10에서는 `JP2002087733A`와 같은 일본 공개번호를 KIPRISPlus의 공개번호 검색으로 조회하여 공식 문헌번호(LTRTNO)로 변환한 뒤 원문 API를 호출합니다. 조회가 불가능할 때의 일본 번호 예비 변환도 `200200087733A0` 형식으로 수정했습니다. Google Patents는 브라우저형 요청 헤더, 영문·일문 페이지, HTML 속성 순서가 다른 PDF 메타태그와 직접 PDF 주소를 순서대로 확인합니다.

6.11에서는 미국·일본·중국을 포함한 외국 공개공보와 등록공보를 구분합니다. Google Patents의 국가별 페이지를 먼저 확인하고, PDF가 없으면 KIPRISPlus 문헌번호(LTRTNO)와 원문 경로를 사용합니다. KIPRISPlus 원문이 PDF가 아닌 ZIP·TIFF·JPEG·PNG·JPEG2000 페이지 묶음이면 파일 수·해제 용량·압축률을 검사하고 페이지 순서대로 하나의 PDF로 변환합니다.

6.12에서는 의견서 등 KIPRIS 문서 팝업이 첫 페이지만 화면 인쇄본으로 저장되는 문제를 방지합니다. PDF.js 뷰어 메모리의 전체 PDF, 브라우저가 수신한 PDF·ZIP·다중 페이지 TIFF, 페이지별 원문 이미지를 순서대로 확인합니다. 뷰어가 표시한 전체 페이지 수보다 저장 결과가 짧으면 불완전 파일을 성공 처리하지 않고 원문 실패로 기록하여 다음 실행에서 다시 시도합니다.

6.13에서는 문헌 폴더·PDF 목록 카드의 최소 높이와 실제 스크롤 목록 높이를 늘렸습니다. 문헌번호 입력란의 예시 줄간격을 줄이고 국가별 번호 예시를 2열로 압축하여 PDF 목록에 더 많은 세로 공간을 배정했습니다. 목록 아래 작업 버튼과 카드 상단 버튼도 조금 작게 조정하여 파일 행을 가리지 않습니다.

항공우주 심사업무에 맞춘 로켓·지구 배경 위에서 오른쪽 대부분을 브라우저의 실제 PDF 뷰어로 사용합니다. 왼쪽에는 여러 문헌 폴더와 선택 폴더의 PDF 파일, 다운로드 설정 및 최소 3줄 높이의 실시간 기록이 표시됩니다. 처리 중에는 진행바가 실시간으로 움직이고 `진행 중` 표시가 점멸합니다.

KIPRIS 문서 팝업의 분석 추적 서버(`gptrk.logger.co.kr`)는 PDF 후보에서 제외합니다. 사내 자체서명 인증서 때문에 별도 요청이 실패하고 원본 PDF 주소도 노출되지 않는 경우에는 숨김 Chrome에 실제 표시된 문서를 마지막 복구 단계에서 PDF로 인쇄 저장합니다.

다운로드 파일명은 `출원번호_출원서.pdf`, `출원번호_의견제출통지서.pdf` 형식을 사용합니다. 동일 종류 문서가 여러 개이면 `_1`, `_2` 순번을 붙여 덮어쓰기를 방지합니다.

- 국내 공개공보 PDF: KIPRISPlus Open API
- 외국 공개·등록공보 PDF: Google Patents 우선 다운로드(기본 선택)
- Google Patents에 PDF가 없으면 KIPRISPlus 해외특허 Open API로 보완
- 의견제출통지서·최후의견제출통지서: KIPRISPlus 의견제출통지서 PDF_V2 API
- 거절결정서: KIPRISPlus 거절결정서 PDF_V2 API
- KIPRIS 통합행정정보에서 원문 열기가 가능한 모든 서류
- 최초출원서·명세서, 보정서, 의견서, 최초·최후 의견제출통지서, 거절·등록결정서 등
- 한 개 원문이 실패해도 나머지 서류 계속 처리

첨부 화면과 같은 통합행정정보 표에서는 파란색 문서명 링크를 다운로드 대상으로 처리합니다. 예시는 다음과 같습니다.

- `[특허출원]특허원서`
- `의견제출통지서`
- `[명세서등 보정]보정서`
- `[거절이유 등 통지에 따른 의견]의견서·답변서·소명서`
- `최후의견제출통지서`
- 그 밖에 파란색 링크와 새 창 아이콘이 표시된 문서

파란색 링크가 아닌 일반 처리이력 행은 원문이 연결되지 않은 것으로 보고 건너뜁니다.

파란 링크가 `javascript:openDocument('출원번호','문서번호','문서코드','')` 형식이면 해당 인수를 읽어 KIPRIS 원문 열기 함수를 직접 실행합니다. 따라서 `[명세서등 보정]보정서` 및 `[거절이유 등 통지에 따른 의견]의견서·답변서·소명서`도 다운로드 대상에 포함됩니다.

공개공보와 API 원문이 제공되는 의견제출통지서·거절결정서는 화면 자동화 없이 먼저 저장합니다. 프로그램은 행정처리 이력 API의 발송번호를 각 `pdfInfoV2` API에 연결합니다. 최초출원서·보정서·의견서 등 API 원문이 제공되지 않는 문서는 KIPRIS 통합행정정보 화면으로 보완합니다.

## KIPRISPlus API 준비

아이디와 비밀번호를 프로그램에 입력하지 않습니다. 다음 절차로 발급받은 REST AccessKey(API Key)만 필요합니다.

1. KIPRISPlus 회원가입 및 로그인
2. 데이터 신청에서 “특허·실용 공개·등록공보” 신청
3. 행정서류용으로 “특허·실용 행정처리 이력”, “의견제출통지서”, “거절결정서” 신청
4. 외국공보도 이용하려면 “해외특허”도 신청
5. 마이페이지의 “API KEY 관리”에서 REST AccessKey 확인
6. “다운로드 설정” 카드 우측 상단의 “설정”을 열어 REST AccessKey 입력 후 “키 저장” 선택

API Key는 설정창에서 가려집니다. “키 저장”을 누르면 Windows 자격 증명 저장소에 안전하게 저장되고 다음 실행 때 자동으로 불러옵니다. 같은 설정창의 “저장된 키 삭제” 버튼으로 지울 수 있습니다. 환경변수 `KIPRIS_API_KEY`가 있으면 그 값을 우선 사용합니다. API Key를 타인에게 전달하거나 메신저·채팅에 붙여넣지 마세요.

## 가장 쉬운 실행 방법

1. 이 ZIP 형태의 일반 배포판은 Windows에 Python 3.11 이상이 필요합니다. 설치 화면에서 “Add python.exe to PATH”를 선택합니다.
2. 압축을 완전히 푼 뒤 install_windows.bat를 한 번 실행합니다. 프로그램 폴더 안에 전용 `.venv` 환경을 만들므로 관리자 권한은 보통 필요하지 않습니다.
3. 설치가 끝나면 `KIPRIS_Document_Hub.vbs`를 더블클릭합니다. 검은 명령창 없이 로컬 웹앱이 실행되고 Chrome 앱 창이 열립니다.
4. 첫 실행에서만 “다운로드 설정” 카드 우측 상단의 “설정”에서 REST AccessKey를 저장합니다. 이후에는 Windows에서 자동으로 불러옵니다.
5. 번호를 직접 붙여넣거나 TXT, CSV, XLSX 파일을 불러옵니다.
6. 다운로드 대상과 저장 폴더를 선택하고 “다운로드 시작”을 누릅니다.

외국번호는 국가코드와 공개·등록 구분코드를 함께 입력합니다. 하이픈과 공백은 자동 제거되며 여러 번호를 줄바꿈·쉼표·세미콜론으로 구분할 수 있습니다.

- 미국 공개: `US20230123456A1`, 미국 등록: `US11234567B2`
- 일본 공개: `JP2002087733A`, 일본 등록: `JP7123456B2`
- 중국 공개: `CN115123456A`, 중국 등록: `CN115123456B`
- 유럽 공개: `EP1731204A1`, 유럽 등록: `EP1731204B1`
- 국제 공개: `WO2020123456A1`

기존 버전에서 6.13으로 교체한 경우 `install_windows.bat`를 다시 실행한 뒤 `preview_windows.bat`로 먼저 확인하세요. 기존 `.venv`를 유지한 채 파일을 덮어쓰면 필수 패키지 확인 후 다운로드 단계를 자동으로 건너뜁니다.

## 새 PC의 Python 설치 여부

- 이 ZIP 배포판: 새 PC에도 Python 3.11 이상을 한 번 설치해야 합니다.
- `build_exe_windows.bat`로 만든 단독 실행형 EXE: 실행할 새 PC에는 Python이 필요하지 않습니다.
- 단독 실행형도 KIPRIS 행정서류 처리를 위해 Google Chrome 또는 Microsoft Edge는 필요합니다.

단독 실행형은 Python과 필수 패키지가 설치된 Windows PC에서 `build_exe_windows.bat`를 실행하면 `dist` 폴더에 생성됩니다. 생성된 EXE를 새 PC로 복사하면 Python을 별도로 설치하지 않아도 됩니다. 단일 EXE는 실행할 때 내부 파일을 임시로 푸는 과정 때문에 일반 ZIP 방식보다 첫 시작이 조금 느릴 수 있습니다.

## 배포 전 실제 미리보기

`preview_windows.bat`를 더블클릭하면 설치 패키지 버전, 필수 파일 및 Python 모듈을 먼저 검사한 다음 웹앱을 진단 모드로 실행합니다. 이 방식도 실제 다운로드 엔진과 HTML 화면을 사용하므로 배포 전에 문헌 1건으로 전체 기능을 시험할 수 있습니다.

1. `install_windows.bat`를 먼저 실행합니다.
2. `preview_windows.bat`를 실행합니다.
3. 검은 진단창을 닫지 않고 자동으로 열린 Chrome에서 문헌 1건을 시험합니다.
4. 서버 오류가 있으면 진단창에 즉시 표시됩니다.
5. 시험이 끝나면 웹 화면 우측 상단 `종료`를 누릅니다.

정상 실행용 `KIPRIS_Document_Hub.vbs`는 명령창을 표시하지 않습니다. 대신 시작에 실패하면 오류 안내창을 표시하고 `%LOCALAPPDATA%\KIPRISDocumentHub\startup.log`에 상세 원인을 기록합니다.

사용자가 보는 HTML 작업 화면과 KIPRIS 자동화용 브라우저는 분리됩니다. 작업 화면은 Chrome 앱 창으로 표시되지만 KIPRIS 자동화 브라우저는 항상 숨김으로 실행됩니다. 자동화에는 설치된 Google Chrome을 먼저 사용하고, 실행할 수 없을 때만 Microsoft Edge를 숨김으로 사용합니다. 문헌별 폴더 아래에 PDF가 저장되고, 실패 내역은 `download_report.csv`와 `document_failures.csv`에 기록됩니다.

숨김 모드에서 파란색 링크를 찾지 못하거나 원문을 한 건도 저장하지 못하면 프로그램이 Chrome 우선 숨김 방식으로 한 번 자동 재시도합니다.

처리가 끝나면 진행바가 100%로 바뀌고 다운로드 폴더를 여는 대신 왼쪽 PDF 목록을 자동으로 갱신합니다. 이어서 화면 상태가 “다운로드 완료”, “일부 실패” 또는 “다운로드 실패”로 바뀌고 결과 요약창이 표시됩니다.

## PDF 폴더·실제 뷰어·병합·텍스트 추출

- 연속 다운로드로 여러 출원번호·공보번호 폴더가 생성되면 “문헌 폴더” 목록에 함께 표시됩니다. 목록은 5개 폴더를 동시에 보여주며 그 이상은 스크롤할 수 있습니다.
- 문헌 폴더를 선택하면 옆의 “PDF 파일” 목록에 해당 폴더의 파일만 표시됩니다. “폴더 열기”를 누르면 선택 폴더를 Windows 탐색기로 엽니다.
- `선택 PDF 삭제`는 체크한 PDF만, `폴더 삭제`는 선택한 문헌 폴더와 그 안의 모든 파일을 Windows 휴지통으로 보냅니다. 휴지통에서 복구할 수 있습니다.
- PDF를 선택하면 오른쪽 전체 영역에 Chrome 내장 PDF 뷰어가 높이 맞춤으로 표시됩니다. 뷰어의 확대·축소, 페이지 이동, 인쇄 및 검색 기능을 사용할 수 있습니다.
- “PDF 합치기·순서”에서 “파일 선택”으로 PDF를 추가하고 `위로/아래로`로 순서를 정한 뒤 생성 파일명을 직접 입력합니다.
- 하나 이상의 PDF 또는 병합 PDF를 선택하고 “텍스트 추출·복사”를 누르면 별도 창에서 추출 결과를 확인할 수 있습니다.
- `외부 PDF 텍스트`를 누르면 KIPRIS에서 받지 않은 다른 폴더의 PDF도 여러 개 선택해 텍스트를 추출할 수 있습니다.
- 추출창의 “전체 복사”로 결과를 클립보드에 복사할 수 있습니다.
- 스캔 이미지로만 구성되어 내장 텍스트가 없는 PDF는 OCR하지 않으며 “추출 가능한 내장 텍스트가 없습니다”라고 표시합니다.

## 입력 형식

국내 출원번호, 국내 공개공보 번호 및 국가코드가 포함된 외국공보 번호를 함께 입력할 수 있습니다. 국내번호만 입력하면 먼저 출원번호로 처리하고, 결과가 없으면 공개번호로 다시 조회합니다.

    1020210171607
    1020250012345A

번호 종류를 명시하면 더 빠르고 정확합니다.

    출원번호,1020210171607
    공개번호,1020250012345A

외국공보는 국가코드와 문헌종류코드를 포함한 전체 번호를 권장합니다.

    US20230123456A1
    EP1731204A1
    WO2020123456A1
    JP2023123456A
    CN115123456A

하이픈과 공백은 자동으로 제거됩니다. 입력창에서는 번호마다 줄을 바꾸거나 쉼표(`,`), 세미콜론(`;`) 또는 탭으로 구분해 여러 번호를 한꺼번에 입력할 수 있습니다. 한 번에 최대 500건입니다. CSV/XLSX는 첫 두 열을 읽으며, “번호”가 포함된 첫 행은 머리글로 처리합니다. 외국번호는 국가코드와 문헌종류코드를 포함한 전체 번호를 입력하세요.

## 외국공보 처리 순서

1. “외국공보 Google Patents 사용”이 선택되어 있으면 Google Patents 문헌 페이지 확인
2. Google이 제공하는 원문 PDF 주소로 저장
3. Google Patents에 PDF가 없으면 KIPRISPlus “해외특허” API에서 공개전문 경로 조회
4. KIPRISPlus PDF 직접 저장

KIPRISPlus 해외특허 API의 주요 제공 국가는 미국(US), 유럽(EP), PCT(WO), 일본(JP), 중국(CN), 대만(TW), 러시아(RU), 콜롬비아(CO), 스웨덴(SE), 스페인(ES), 이스라엘(IL), 인도(IN), 베트남(VN)입니다. Google Patents 우선 경로는 해당 문헌 페이지에 PDF 링크가 있는 경우에 동작하며, 링크가 없으면 KIPRISPlus로 자동 보완합니다.

## 알아둘 점

- 웹 화면은 인터넷에 공개되는 웹사이트가 아닙니다. 프로그램은 `127.0.0.1`에만 연결되는 로컬 서버로 실행됩니다.
- 실행할 때마다 임의의 세션 토큰을 만들고 변경 요청과 PDF 접근을 검증합니다. 외부 웹페이지에서 로컬 다운로드 기능을 호출하지 못하도록 CORS 미허용, CSP 및 보안 헤더를 적용했습니다.
- REST AccessKey는 HTML·JavaScript·일반 설정 파일로 전달하지 않으며, Windows 자격 증명 저장소에서 Python 처리부가 직접 읽습니다.
- 프로그램을 완전히 끝내려면 화면 우측 상단의 `종료` 버튼을 사용하세요. 다운로드 중에는 먼저 `중지`를 눌러 현재 문서 처리가 끝난 뒤 종료합니다.

- 국내 공개공보 API에는 “특허·실용 공개·등록공보” 이용권한이 필요합니다.
- 행정목록 조회에는 “특허·실용 행정처리 이력”, PDF 원문에는 “의견제출통지서” 및 “거절결정서” 이용권한이 필요합니다.
- 외국 공개·등록공보 API에는 “해외특허” 이용권한이 필요합니다.
- KIPRIS 통합행정정보에서 원문 링크 또는 원문 버튼이 제공되는 모든 공개 행정문서를 저장 대상으로 처리합니다.
- 비공개 문서, 원문이 연결되지 않은 행, 아직 공개되지 않은 출원은 내려받을 수 없습니다.
- 개별 원문 저장 실패는 해당 출원 폴더의 `document_failures.csv`에 기록하고 다음 서류를 계속 처리합니다.
- 원문 저장은 직접 다운로드, PDF 네트워크 응답, 새 창 PDF 뷰어, Blob PDF 순서로 가능한 방식을 자동 선택합니다. 별도 HTTP 요청이 사내 자체서명 인증서 때문에 실패하면 로그인 쿠키를 유지한 Chrome 페이지 내부에서 같은 URL을 다시 요청합니다. 원본 바이너리를 끝내 찾지 못하면 숨김 Chrome에 표시된 문서를 인쇄 PDF로 저장하므로 원본 PDF와 페이지 여백·링크 등의 속성이 다를 수 있습니다.
- 외국 문헌의 출원서·심사서류는 이 프로그램의 대상이 아닙니다.
- KIPRIS 화면 구조가 변경되면 국내 행정서류 부분의 선택자 수정이 필요할 수 있습니다.
- 너무 빠른 반복 접속을 피하기 위해 문헌 사이에 대기시간을 둡니다.
- 한 번에 최대 500건, PDF 한 파일 최대 500MB, 병합 최대 10,000페이지로 제한합니다.
- PDF 병합·텍스트 추출과 다운로드는 HTML 화면과 분리된 Python 처리부에서 실행합니다.
- 다운로드와 병합 결과는 임시파일 검증 후 최종 파일로 교체하여 중단 시 기존 정상 파일을 보호합니다.
- 외부 PDF는 HTTPS 및 KIPRIS/Google 특허 원문 허용 도메인만 접속합니다.
- KIPRIS 화면에는 원본보기 서비스에 일부 오류·누락이 있을 수 있으므로 정확한 서류는 특허로에서 확인하라는 안내가 표시됩니다.
- 내려받은 자료의 이용과 출처 표시는 KIPRIS 및 Google 정책과 관련 법령을 따라야 합니다.

## 문제 해결

- `KIPRIS_Document_Hub.vbs`를 눌러도 아무 반응이 없음: `preview_windows.bat`를 실행하여 진단창의 오류를 확인합니다. 정상 실행 경로에서 시작에 실패하면 `%LOCALAPPDATA%\KIPRISDocumentHub\startup.log`에도 기록됩니다.
- 프로그램과 함께 검은 명령창이 표시됨: 진단이 끝난 뒤에는 `preview_windows.bat` 대신 `KIPRIS_Document_Hub.vbs`를 사용합니다. VBS 런처는 가상환경의 `pythonw.exe`로 프로그램을 실행합니다.
- 오른쪽 PDF 기능이 실행되지 않음: 새 ZIP을 별도 폴더에 풀고 `install_windows.bat`를 다시 실행하여 PyMuPDF를 설치합니다.

- `ModuleNotFoundError: No module named 'playwright'`: 새 버전의 압축파일로 교체한 뒤 압축을 풀고 `install_windows.bat`를 다시 실행합니다. 설치가 끝나기 전에 창을 닫지 마세요.
- `액세스가 거부되었습니다` 또는 `臾몄꽌...` 같은 깨진 글자: 이전 배치 파일의 한글 인코딩 문제입니다. 새 버전은 배치 파일을 영문 명령으로 바꾸고 프로그램 폴더의 전용 Python 환경을 사용합니다.
- `self-signed certificate in certificate chain`: 5.1부터 KIPRIS 팝업 원문은 먼저 로그인 쿠키가 유지된 Chrome 세션 내부 방식으로 자동 재시도합니다. 기본 보안 설정으로 먼저 실행하세요. 그래도 실패하면 회사 루트 인증서 설치를 사내 보안 담당자에게 요청하고, 불가피한 경우에만 다운로드 설정 카드의 `설정`에서 “HTTPS 인증서 오류 임시 허용”을 켭니다.
- Chromium 다운로드 오류: 별도 Chromium을 다운로드하지 않고 Windows에 설치된 Google Chrome을 우선 사용합니다. 새 ZIP을 별도 폴더에 풀고 `install_windows.bat`를 다시 실행합니다.
- Google Chrome 실행 오류: Chrome이 설치·업데이트되어 있는지 확인합니다. Chrome을 실행할 수 없으면 Microsoft Edge를 두 번째 순서로 시도합니다.
- 회사 보안 정책으로 Python 패키지 설치까지 차단되는 경우에는 사내 프록시·방화벽 설정을 전산 담당자에게 문의합니다.
- 인증 오류 또는 `AccessKey&ServiceID Is Not Registered`: REST AccessKey와 오류가 난 데이터 상품(행정처리 이력·의견제출통지서·거절결정서 포함)의 신청 상태를 확인합니다.
- 국내 검색결과 없음: 입력값을 “출원번호,번호” 또는 “공개번호,번호”로 명시합니다.
- 외국공보 실패: 국가코드와 문헌종류코드를 포함했는지 확인합니다(예: US20230123456A1).
- 일부 서류만 없음: 해당 통합행정정보 행에 원문 링크가 없거나 개별 원문 열기에 실패한 경우입니다. 해당 출원 폴더의 `document_failures.csv`를 확인합니다.
- 공개공보 경로가 HTTP라서 차단됨: 5.2부터 허용된 KIPRIS·Google 특허 원문 서버가 돌려준 HTTP 주소만 HTTPS로 자동 승격합니다. 그 밖의 HTTP 주소와 미허용 서버는 계속 차단합니다.
- 공개공보만 저장됨: 진행 기록에서 `원문 링크 감지`, `통합행정정보 원문 후보`, `PDF 네트워크 응답` 또는 `숨김 방식 자동 재시도` 메시지를 확인합니다.
- `strict mode violation: button[type="submit"] resolved to ... elements`: KIPRIS의 실제 검색 버튼(`btn-search`, `rightTotalSearch`)을 정확히 지정합니다.
- `modalSearchDetail ... intercepts pointer events`: 활성 상세검색 창을 닫고, 필요하면 KIPRIS 검색 함수를 직접 실행합니다.
- `Target page, context or browser has been closed`: 검색 결과가 새 창으로 열리거나 기존 창을 교체해도 살아 있는 상세화면을 다시 선택합니다.
- 보정서·의견서 링크를 찾았지만 원문 창이 열리지 않음: 링크 안의 `openDocument` 인수를 읽어 함수를 직접 호출하며, 실패하면 팝업 차단을 해제한 Chrome에서 강제 링크 클릭으로 다시 시도합니다.
- 다운로드 중지: “중지”를 누르면 현재 문서 처리가 끝난 뒤 안전하게 중지하며 진행바는 실제 처리된 문헌까지만 표시합니다.
- 중단 후 재실행: 정상 PDF는 건너뛰고 비정상·부분 파일은 임시파일 검증 후 다시 저장합니다.

## EXE 만들기(선택)

build_exe_windows.bat를 실행하면 dist 폴더에 EXE가 만들어집니다. 브라우저는 EXE에 포함하지 않으며 대상 PC에 설치된 Microsoft Edge 또는 Google Chrome을 사용합니다.
